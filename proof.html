01 / Internlog: case study

Internlog

An anonymous internship-review platform with an explainable fraud and spam detector.

Node/Express · Supabase · Render

Internlog on GitHub ↗ Live site ↗

Free hosting: the first load can take a few seconds to wake up.

Built with Suhaas Voruganti.

What it is

Students browse and submit internship reviews, company ratings and interview experiences. Submissions are screened by a rule-based detector that scores five signals: lexical diversity, near-duplicate similarity, rating extremity, templated language and link spam. It shows moderators why a review was flagged instead of rejecting it automatically.

What I built

  • Moved storage from flat JSON files to Supabase Postgres with four tables and row-level security enabled.
  • Wrote the data-access layer so the frontend needed no changes after the migration.
  • Added moderation workflows, email notifications through the Brevo API, and rate limiting.
  • Did a full mobile pass: hamburger nav, responsive CSS, small-phone breakpoint at 380px.
  • Set up GitHub Actions CI/CD and CodeQL security scanning, plus uptime monitoring.
  • Ran a security hardening pass: admin-gated write endpoints, an XSS fix, a query fix that protects the database connection pool, 36 automated tests that run on every push, and every npm audit finding cleared (Nov 2026).

Architecture

Node/Express 5 REST API; vanilla HTML/CSS/JS frontend with no framework; Postgres on Supabase via a pg connection pool over the IPv4-compatible session pooler (migrated from the original JSON-file storage); Render hosting with deploys on pushes to main and UptimeRobot pings to avoid free-tier spin-down; Brevo HTTPS email API instead of Gmail SMTP because Render's free tier blocks outbound SMTP ports; configuration through environment variables.

Backend practices

Parameterized SQL; mapper functions from snake_case rows to a camelCase API; a shared asyncRoute wrapper for consistent error handling; idempotent INSERT … ON CONFLICT SQL for data fixes and restores; the company list built from one aggregated query instead of one query per company; clean URLs with a 301 from /page.html to /page.

Explainable fraud detector

A transparent, rule-based Stage 1 scorer (not a trained model) with no dependencies. It checks five signals: length and vocabulary diversity, near-duplicate similarity (Jaccard similarity on word 3-gram shingles against the company's existing reviews), rating extremity (a 1 or 10 paired with thin text), generic or templated phrasing, and links (with extra weight for commonly abused domains). It produces a 0–100 score, a level (low, medium or high) and plain-English reasons, stores all three with the review, and adds them to the moderation email. It never auto-rejects, so a human makes the final call. I chose a rule-based scorer over a separate ML microservice on purpose: every flag has to be explainable, and there's no labeled data yet to train on.

Security

Tiered rate limiting (general, write, admin) with trust proxy set correctly behind Render; server-side validation (rating 1–10, 250-word limit per field); an admin key, compared in constant time, required to create or edit companies and to delete reviews (401 without it); escapeHtml() on user-controlled output, including quotes, which closed an attribute-injection hole in the company dropdown (the first XSS fix came from a CodeQL finding); row-level security enabled on the tables with no policies and server-only access; no user accounts, so little personal data; Privacy Policy, Terms and SECURITY.md plus a required policy-agreement checkbox; CodeQL and Dependabot scanning; 36 automated tests on every push.

Hardening pass (Nov 2026)

  • Company create and edit endpoints were open. They now need the admin key and return 401 without it, confirmed with a live request in production.
  • The company list ran one query per company, which could exhaust Supabase's 15-connection pool as the site grew. It's now one aggregated query.
  • escapeHtml() didn't escape quotes, which allowed attribute injection. Fixed and covered by tests.
  • Added 36 tests (admin auth, rate-limit tiers, the single-query behavior, escaping, the fraud scorer) that run in GitHub Actions on every push.
  • Removed an unused email dependency, upgraded to Express 5 and cleared every npm audit finding.

Moderation and product

An email for every new review and report; a report modal for community flagging; a scope guardrail that keeps the site internships-only; company verification and tiering (Bronze, Silver, Gold) with leaderboards; search, role filtering and sorting; loading spinners; SEO and Open Graph tags; launch README with badges.

How I work

Prototype in a sandbox, then hand off tested code. I ran the scorer against realistic good and junk reviews before it touched the repo, and verified each step with syntax checks, grep, a local boot and a live end-to-end test (a thin review got flagged, a real one did not). I pull before pushing and resolve merge conflicts with the security fix preserved. After an accidental mass deletion, I rebuilt the data from the moderation emails.

What I learned

Supabase's direct connection is IPv6-only, so Render's free tier needs the session pooler. Render's free tier blocks SMTP ports, so email has to go over an HTTPS API.

What I'm improving next

  • Add automated database backups.
  • Record moderator decisions. Deleting a review currently removes its row, so the outcome is lost. Keeping decisions next to the stored score and reasons is the prerequisite for a labeled dataset and a future trained stage.

02 / FlyRank ML internship track

Search Content Decline Analysis

A reproducible pipeline that ranks 30,000 pages for content refresh and tests whether a model beats a simple rule.

  • Built a Python, pandas and scikit-learn pipeline on an anonymized 30,000-page search dataset.
  • Compared a hand-written rule against decision trees using Precision@K. At K=50 the depth-2 and depth-3 trees scored 0.60 and 0.72 against 0.68 for the rule, measured in-sample.
  • Tested whether keyword search volume predicts impressions. The correlation was about 0.00 across all 30,000 pages and across the 21,994 pages with 100+ impressions.
  • Demonstrated how target leakage inflates results.

Honesty note These numbers are in-sample, so they don't show that the trees beat the rule.

03 / Open-source Claude skill

Checkpoint Study Path

A free, open-source Claude skill that turns your slides into a study plan and a mastery-gated quiz.

It builds a study plan from course materials, computes the score needed, groups questions into checkpoints instead of chapters, brings missed questions back three questions later, and checks answer keys with a script. MIT license, built for students.

Requires a paid Claude plan.

A 30-second pixel-art demo with a music soundtrack and no narration. Every message is shown as on-screen text. It opens with "Exam in 9 days" and a wall of lecture decks and homework, then the title "Checkpoint Study Path, an exam-prep skill for Claude". A study plan shows the score needed on the final and a week-by-week timeline. A checkpoint map shows a cleared checkpoint unlocking the next, and a missed question coming back three questions later. A mixed review draws ten random questions from cleared checkpoints, and a review loop follows. It ends on the slash command and the GitHub link.
